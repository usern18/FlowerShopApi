# Performance Testing — FlowerShopApi

**Дата вимірювань:** 06.11.2026  
**Застосунок:** FlowerShopApi (ASP.NET Core, Kestrel), Docker Compose + MySQL 8.0  
**Тестований маршрут:** `GET /api/products`  
**Середовище:** ApacheBench та k6 у тимчасових Docker-контейнерах у мережі `flowershopapi_default`, API за адресою `http://flowershopapi:8080` усередині мережі. На хості API доступний через `localhost:5239`.

## 1. Мета

Оцінити пропускну здатність, затримки та частоту помилок HTTP API за різного рівня паралельності та кількості віртуальних користувачів. Перевірити критерії працездатності: частка невдалих запитів менше 1% та p95 менше 1000 мс.

## 2. Benchmark Testing — ApacheBench

Кожен тест надсилав 1000 запитів без запланованих пауз. Змінювався параметр паралельності `-c`.

| Показник | c = 5 | c = 20 | c = 50 |
|---|---:|---:|---:|
| Кількість запитів | 1000 | 1000 | 1000 |
| Тривалість, с | 0,678 | 0,332 | 0,197 |
| Запитів/с | 1474,88 | 3008,65 | 5077,79 |
| Time per request (mean), мс | 3,390 | 6,647 | 9,847 |
| p95, мс | 4 | 11 | 14 |
| Максимальна затримка, мс | 51 | 61 | 32 |
| Failed requests | 0 | 0 | 0 |

Приклади запуску:

```powershell
docker run --rm --network flowershopapi_default httpd:2.4-alpine `
  ab -n 1000 -c 5 http://flowershopapi:8080/api/products

docker run --rm --network flowershopapi_default httpd:2.4-alpine `
  ab -n 1000 -c 20 http://flowershopapi:8080/api/products

docker run --rm --network flowershopapi_default httpd:2.4-alpine `
  ab -n 1000 -c 50 http://flowershopapi:8080/api/products
```

**Інтерпретація:** при збільшенні паралельності з 5 до 50 запитів пропускна здатність зросла з 1474,88 до 5077,79 запиту/с. Водночас p95 зріс із 4 до 14 мс. Усі три короткі запуски завершилися без невдалих запитів.

## 3. Stress Testing — k6 (поступове навантаження)

Сценарій: 30 с — розгін до 10 VU, наступні 30 с — до 50 VU, наступні 30 с — до 100 VU, останні 30 с — спад до 0 VU. Після кожного GET-запиту виконувалася пауза `sleep(1)`.

| Показник | Фактичне значення |
|---|---:|
| Тривалість активних стадій | 120 с |
| Максимальна кількість VU | 100 |
| HTTP-запитів | 4825 |
| Середня швидкість | 40,014 запиту/с |
| Середня затримка | 1,34 мс |
| Медіанна затримка | 1,2 мс |
| p90 | 1,67 мс |
| p95 | 2,18 мс |
| Максимальна затримка | 102,08 мс |
| Невдалі HTTP-запити | 0 із 4825 (0%) |
| Перевірки статусу `200` | 4825 із 4825 (100%) |
| p95 < 1000 мс; помилки < 1% | Обидва критерії виконано |

Ці цифри є підсумком за **весь сценарій**, а не окремо за конкретною кількістю VU.

## 4. Stress Testing — k6 (фіксована кількість VU)

Кожен тест тривав 30 секунд. Застосовано `sleep(1)` після кожного запиту.

| Показник | 10 VU | 50 VU | 100 VU |
|---|---:|---:|---:|
| Кількість HTTP-запитів | 300 | 1500 | 3000 |
| Запитів/с | 9,962 | 49,805 | 99,278 |
| Середня затримка, мс | 3,00 | 3,17 | 4,11 |
| Медіана, мс | 2,36 | 2,44 | 2,45 |
| p90, мс | 4,77 | 5,97 | 5,83 |
| p95, мс | 5,00 | 7,02 | 8,27 |
| Максимальна затримка, мс | 16,00 | 23,76 | 106,45 |
| HTTP-помилки | 0% | 0% | 0% |
| Успішні перевірки `200` | 100% | 100% | 100% |

Команда запуску (приклад для 50 VU):

```powershell
docker run --rm --network flowershopapi_default `
  -v "${PWD}/performance:/scripts:ro" `
  -e VUS=50 grafana/k6 run /scripts/stress-test.js
```

При 100 VU усі 3000 запитів завершилися з HTTP 200; p95 становив 8,27 мс, що нижче обраного порога 1000 мс.

## 5. Пояснення відмінностей ApacheBench і k6

ApacheBench надсилав запити без штучної затримки, тоді як k6 мав паузу `sleep(1)` для кожного VU, тому швидкості запитів за секунду **не можна безпосередньо порівнювати як однаковий тип навантаження**. Запити також проходили всередині Docker-мережі, без моделювання інтернет-затримок реальних користувачів.

## 6. Обмеження

- ApacheBench-тести тривали менше однієї секунди кожен, тому результати можуть залежати від прогріву застосунку, кешу, планувальника та умов виконання.
- k6 перевіряв лише маршрут `GET /api/products`, а не створення замовлень, авторизацію чи інші операції.
- 100 VU — максимальний **перевірений** рівень у сценарії; межу відмови або насичення системи не встановлено.
- Вимірювання не містять окремих метрик використання CPU, RAM або MySQL; їх слід зібрати під час профілювання.
- Для підвищення відтворюваності варто повторити кожен тест кілька разів, зафіксувати параметри комп'ютера та версії інструментів.

## 7. Висновок

За результатами проведених вимірювань FlowerShopApi успішно обробляв запити до `GET /api/products` за перевірених навантажень. У трьох запусках ApacheBench виконано 3000 запитів без помилок; найбільша короткочасна пропускна здатність у цій серії становила 5077,79 запиту/с при `c=50`. У k6 за поступового збільшення навантаження до 100 VU виконано 4825 запитів без помилок. За фіксованих 100 VU виконано 3000 запитів за 30 с, p95 = 8,27 мс, частка HTTP-помилок = 0%. Обидва задані пороги k6 виконано. Ці результати підтверджують працездатність **у перевірених умовах**, а не абсолютну максимальну продуктивність.
